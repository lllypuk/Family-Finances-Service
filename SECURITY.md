# Политика безопасности

## Поддерживаемые версии

Проект разворачивается самостоятельно (self-hosted) и выпускается без долгоживущих
веток поддержки. Исправления выходят только для актуального состояния `main`.

| Версия | Поддержка |
|---|---|
| `main` | ✅ |
| теги релизов | ❌ (обновитесь до `main`) |

## Как сообщить об уязвимости

Сообщайте приватно через **GitHub Security Advisories**:
[Report a vulnerability](https://github.com/lllypuk/Family-Finances-Service/security/advisories/new).

Не заводите публичный issue для уязвимостей — это раскрывает проблему всем
развёрнутым экземплярам до появления исправления.

Что полезно приложить:

- затронутый эндпоинт или файл и версию (коммит `main`);
- шаги воспроизведения либо PoC-запрос;
- какие данные или действия становятся доступны;
- конфигурацию развёртывания, если она важна (Docker Compose, systemd, nginx/Caddy).

Ориентировочные сроки: подтверждение получения — в течение 7 дней, оценка и план
исправления — в течение 30 дней. Проект ведёт один мейнтейнер в свободное время,
поэтому это ориентир, а не SLA.

## Что входит в область рассмотрения

- обход аутентификации и авторизации REST API (`/api/v1`);
- доступ к данным чужой семьи или чужого пользователя;
- SQL-инъекции, обход аутентификации по bearer-токену или лимитера логина;
- утечка или подделка токенов сессий;
- уязвимости в цепочке сборки (Dockerfile, GitHub Actions workflows).

## Что не входит

- Развёртывания, где `TRUSTED_PROXIES` включает недоверенный прокси: лимитер логина
  верит `X-Forwarded-For` только от перечисленных там сетей.
- Сценарии, требующие уже полученного доступа администратора семьи.
- Отчёты автоматических сканеров без демонстрации эксплуатации.

## Практики безопасности в репозитории

- Все GitHub Actions пришпилены по коммит-SHA, базовые Docker-образы — по дайджесту;
  обновления приходят через Dependabot.
- На каждый push и pull request выполняются CodeQL, Semgrep, govulncheck,
  OSV Scanner и TruffleHog (`.github/workflows/security.yml`), еженедельно —
  OSSF Scorecard (`.github/workflows/scorecard.yml`).
- Токен `GITHUB_TOKEN` по умолчанию ограничен `contents: read`; write-скоупы
  выдаются точечно отдельным джобам.
