# core:api

Единственный модуль, знающий о сети: сгенерированные модели и Retrofit-интерфейсы плюс транспорт.

## Генерация

`generated/kotlin` — вывод `openapi-generator-cli` из `docs/api/openapi.yaml`, он **коммитится** и
руками не правится. Задача `generateApiClient` (`make -C android api-gen`) чистит каталог перед
запуском, поэтому выпавшая из спеки схема не остаётся мусором.

Генерация не входит ни в `compile`, ни в `check`: она тянет генератор и его зависимости из сети, а
обе цели обязаны работать офлайн. Свежесть проверяет `make -C android api-check` (перегенерация +
`git status --porcelain` по каталогу) и отдельный шаг CI.

Из вспомогательных файлов генератора берётся только `infrastructure/CollectionFormats.kt` — его
импортируют интерфейсы; остальные принесли бы чужие `build.gradle`, `README.md` и `docs/`.

## Что нужно помнить о выводе

- Пути в интерфейсах полные (`api/v1/...`), значит базовый адрес — корень хоста со слэшем.
- `amount_minor` → `Long`, дата → `LocalDate`, `created_at` → `OffsetDateTime`, `id` → `UUID`;
  все `@Contextual`, и без зарегистрированных сериализаторов не разбирается даже логин —
  `meta.timestamp` есть в каждом ответе.
- Имена конвертов из `components/responses` держатся схемами `*Ok` в `components/schemas`:
  инлайновые дали бы позиционные `InlineObject…`, которые сдвинет седьмая такая схема.
