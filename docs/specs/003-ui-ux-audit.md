# 003 — Аудит интерфейса

**Дата:** 16.08.2026 · **Метод:** реальный Chrome через `agent-browser`, axe-core 4.12.1

Пройден полный сценарий: первичная настройка → вход → дашборд → создание категории →
создание транзакции → просмотр списка. **Основной поток работает.** Транзакция
создалась, попала в список и корректно отобразилась (`-1500.00 ₽`, категория,
дата). Дефолтные категории (Продукты, Транспорт, Зарплата и ещё 10) создаются
автоматически при setup — хорошее решение, новый пользователь сразу может работать.

Ниже — то, что сломано.

## U-01 — Страница первичной настройки грузится без стилей {#u-01}

**Приоритет: P1.** Это первое, что видит человек на новом сервере.

`middleware.RequireSetup` зарегистрирован глобально и пропускает только `/setup`.
Всё остальное получает 302 — **включая CSS, JS и `/health`**:

```bash
# на свежей установке, до завершения setup
curl -o /dev/null -w "%{http_code}\n" 127.0.0.1:8090/static/css/pico.min.css   # 302
curl -o /dev/null -w "%{http_code}\n" 127.0.0.1:8090/health                     # 302
```

Браузер запрашивает `/static/css/pico.min.css`, получает редирект на `/setup`, в
ответ приходит HTML — и стили не применяются. Страница отрисовывается дефолтным
Times New Roman с нативными полями ввода и битой иконкой на кнопке.

После завершения настройки всё чинится само (проверено: оба URL отдают 200), поэтому
баг легко не заметить в разработке — он виден ровно один раз, на первом запуске.

Побочный эффект: `/health` до настройки отдаёт 302. Docker HEALTHCHECK на `wget`
переживёт (wget идёт по редиректу), но любой внешний мониторинг, ожидающий 200,
покажет свежеразвёрнутый сервис как упавший.

**Причина:** `internal/web/web.go:85-88` — `Static` регистрируется, затем глобальный
`Use(RequireSetup)` перехватывает всё, включая уже зарегистрированные маршруты.

**Что делать:** в `RequireSetup` пропускать `/static/*`, `/health` и favicon до
любых проверок.

## U-02 — Навигация пропадает на всех страницах-списках {#u-02}

**Приоритет: P1.**

На `/transactions`, `/budgets`, `/categories`, `/reports` в шапке остаётся только
логотип. Меню (Главная · Транзакции · Категории · Бюджеты · Отчёты · профиль)
исчезает — уйти со страницы можно лишь кликнув по логотипу.

При этом на `/transactions/new` меню есть. То есть поведение непоследовательно
между списком и формой.

**Причина — рассогласование контракта данных.** Дашборд передаёт данные встроенной
структурой, поэтому `.CurrentUser` виден в корне:

```go
// dashboard.go:110 — работает
data := struct {
    *PageData
    *webModels.DashboardViewModel
    Filters *webModels.DashboardFilters
}{PageData: pageData, …}
```

Остальные хендлеры передают map, где `PageData` вложен ключом:

```go
// transactions.go:102 — навигация ломается
data := map[string]any{
    "PageData": pageData,   // CurrentUser теперь на .PageData.CurrentUser
    …
}
```

А шаблон проверяет корень:

```html
{{if .CurrentUser}}   <!-- всегда false → весь блок меню молча выпадает -->
```

Go-шаблоны считают отсутствующий ключ map нулевым значением и не выдают ошибку —
поэтому баг тихий. Тесты его не ловят, потому что рендерер в тестах замокан
(`MockRenderer` возвращает `nil`, ничего не рендеря).

**Что делать:** привести все хендлеры к одному контракту (лучше — к встроенной
структуре, как на дашборде) и добавить тест, который рендерит настоящий шаблон и
проверяет наличие меню.

## U-03 — Мобильная вёрстка непригодна {#u-03}

**Приоритет: P1.** Семейный бюджет — это в первую очередь телефон.

При ширине 390px (iPhone 12) меню разворачивается в вертикальный столбец из шести
пунктов и съедает ~420px до начала контента. Бургер-меню нет — это поведение
PicoCSS `<nav><ul>` по умолчанию, оставленное без адаптации.

Дальше по странице карточки KPI встают в одну колонку, и дашборд пустого аккаунта
растягивается на несколько экранов прокрутки.

**Что делать:** свернуть навигацию в `<details>`-бургер на узких экранах (PicoCSS
это умеет без JavaScript, что укладывается в правило «без кастомного JS»).

## U-04 — Общего макета фактически нет {#u-04}

**Приоритет: P2.** Причина U-02 и половины расхождений в оформлении.

```bash
grep -rln 'template "base' internal/web/templates/   # ничего не найдено
```

`layouts/base.html` **не используется никем** — это мёртвый код. Вместо него **20
шаблонов страниц** содержат по собственной полной копии HTML-документа: свой
`<head>`, свой инлайн-дубликат навигации, свой футер.

Следствия:

- `components/nav.html` и `components/footer.html` тоже мертвы — их подключает
  только `base.html`.
- `dashboard-colors.css` подключён **только** из мёртвого `base.html`, то есть не
  загружается никогда. Файл лежит в репозитории и не влияет ни на что.
- `compact.css` подключён только на дашборде.
- Любая правка шапки требует 20 одинаковых правок.
- `© 2025` захардкожен минимум в 5 файлах — на дворе 2026.

**Что делать:** ввести настоящий макет. Технически в Go-шаблонах это делается через
`{{define "content"}}` в странице + один `base`, который уже написан и просто ждёт
подключения.

## U-06 — Доступность: контраст ниже WCAG AA {#u-06}

**Приоритет: P2.** axe-core, правила `wcag2a,wcag2aa`, дашборд:

```
violations: 1   incomplete: 1   passes: 24

[serious] color-contrast (6 узлов)
  - h1                                    ← «Добро пожаловать, Админ!»
  - .welcome > p                          ← подзаголовок практически не читается
  - .checked > span
  - .action-btn.secondary[href$="categories"]
  - a[href="/transactions?category=top"]
  - button[hx-target="#insights-export"]
```

Визуально это подтверждается: приветственный баннер — тёмно-синий текст на синей
плашке, подзаголовок «Вот обзор финансов вашей семьи» почти сливается с фоном.
Нижний ряд кнопок («Управление категориями», «Экспорт данных») — серый на сером,
выглядит как отключённые элементы.

Остальные 24 проверки пройдены: у форм есть подписи, есть `lang="ru"`, есть
skip-link. Проблема точечная — только палитра.

## Оценка дизайна и предложение по направлению

**Что есть сейчас.** PicoCSS почти без настройки плюс один акцентный синий,
использованный без иерархии. Четыре кнопки «Быстрых действий» идут сплошными синими
полосами во всю ширину и перетягивают на себя внимание с реальных данных. Блок
«Состояние бюджетов» выкладывает четыре счётчика вертикально, хотя KPI-строка выше
показывает те же четыре карточки горизонтально — два разных решения для одной задачи
на одном экране. Пустой дашборд занимает 3761px по высоте.

Итог: интерфейс не уродлив, он **безличен и разрежен**. Ощущение админки, а не
приложения о семейных деньгах.

**Предложение — «Бумажная бухгалтерская книга».** Направление, взятое из предмета:
семейный бюджет исторически — это тетрадь, куда от руки заносят приход и расход.
Отсюда:

- **Плотность вместо воздуха.** Таблица транзакций — главный экран, а не карточки
  со счётчиками. Строка операции должна быть компактной, как строка в тетради;
  на экран телефона должно помещаться 12–15 операций, а не 4.
- **Числа как типографика.** Суммы — единственный элемент, которому разрешён
  крупный кегль и табличные цифры (`font-variant-numeric: tabular-nums`), чтобы
  разряды выстраивались по вертикали. Сейчас суммы набраны тем же шрифтом, что и
  подписи, и не читаются колонкой.
- **Цвет несёт смысл, а не украшает.** Ровно три цвета данных: приход, расход,
  превышение лимита. Синий уходит из декоративных плашек и остаётся только на
  одном первичном действии страницы. Это заодно закрывает U-06.
- **Один акцент на экран.** На дашборде это «Добавить транзакцию». Остальные
  действия — текстовые ссылки. Четыре одинаково кричащие кнопки не задают приоритет,
  а снимают его.
- **Эмодзи — только там, где их выбрал пользователь** (иконка категории). В
  системных элементах — единый набор inline-SVG.

Направление сознательно совместимо с ограничениями проекта: PicoCSS 2.1.1 и HTMX
2.0.4 остаются, кастомный JS не нужен, всё делается переменными CSS и правкой
шаблонов. Это не редизайн с нуля, а наведение порядка в том, что уже написано.
