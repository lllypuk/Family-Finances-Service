- **Автообновлений больше нет.** Dependabot остался на GitHub вместе с `.github/`, а GitLab CE
  своего аналога не даёт. Руками обновляются: модули Go (`go get -u`), дайджесты `FROM` в
  `docker/Dockerfile`, дайджест образа Caddy в `deploy/docker-compose.yml` и версии инструментов
  в `.gitlab-ci.yml` (`GOLANGCI_LINT_VERSION`, `GOVULNCHECK_VERSION`), а также версии клиента в

  openapi-generator, ktlint) и `CMDLINE_TOOLS_URL`/`ANDROID_PACKAGES` в `.gitlab-ci.yml` —
  Gradle-зависимости не смотрит вообще ничто.
  `govulncheck` в пайплайне поймает уязвимую версию Go-зависимости, но не устаревший базовый образ.

## Сервер: находки при планировании бюджетов в клиенте (11.09.2026)

Найдено при [плане 07](plans/completed/20260911-07-android-budgets.md), проверено по коду вместе с codex;
клиент обходит их, сервер не менялся.

- **`is_active` у бюджета — односторонний.** `listBudgets` и без `active_only`, и с
  `active_only=false` отдаёт только `is_active = 1`
  (`internal/infrastructure/budget/budget_repository_sqlite.go:221`), а `DELETE` — мягкое удаление
  тем же флагом (`:587`). Бюджет, выключенный через `PUT {is_active: false}`, исчезает из всех
  списков без пути назад, и от удалённого его не отличить. Либо убрать `is_active` из
  `UpdateBudgetRequest`, либо развести «выключен» и «удалён» в схеме и вернуть выключенные при
  `active_only=false`. Клиент `is_active` не показывает.
- **Бизнес-отказы бюджета неразличимы для клиента.** Пересечение периодов, занятое имя и сумма
  меньше потраченного уходят одной веткой как `422 VALIDATION_ERROR` с `details[{field: "body",
  code: VALIDATION_ERROR}]` (`internal/application/handlers/budgets.go:355`): отличить их можно
  только по английскому `message`. Нужны свои коды (`BUDGET_OVERLAP`, `BUDGET_NAME_EXISTS`,
  `BUDGET_BELOW_SPENT`) или `409`, как у `CURRENCY_LOCKED` — тогда клиент переведёт. Сейчас клиент
  показывает один общий русский текст.
- **Граничный день попадает в два бюджета одной категории.** Проверка пересечения строгая —
  `end` первого может равняться `start` второго (`internal/services/budget_service.go:592`), а
  расходы считаются по включительным границам (`transaction_repository_sqlite.go:781`). Либо
  нестрогая проверка, либо документировать в `openapi.yaml`. Клиентские пресеты периодов делают
  конец = начало + N − 1 день, так что подряд идущие бюджеты из приложения не пересекаются.
- **`PUT` проверяет новую сумму против расхода по старым датам** (`budget_service.go:233`, `:266`):
  сузить период и одновременно уменьшить лимит нельзя, даже если по новому периоду расход
  укладывается. Клиент шлёт только изменённые поля, но этот случай всё равно даёт 422.

## Сервер: находки при планировании настроек в клиенте (11.09.2026)

Найдено при [плане 08](plans/completed/20260911-08-android-settings.md), проверено по коду вместе с
codex; клиент их обходит, сервер не менялся.

- **`PUT /users/:id` отдаёт `409 EMAIL_TAKEN`, которого нет у этой операции в `openapi.yaml`**
  (`internal/services/user_service.go:181`, `handlers/users.go:39`). Клиент код обрабатывает;
  дописать ответ в спеку — это потянет перегенерацию Android-клиента, поэтому отдельной задачей.
- **Пароль и деактивация записываются до отзыва сессий** (`internal/auth/service.go:211`,
  `user_service.go:222`): сбой отзыва — `500`, но новый пароль или снятый `is_active` уже в базе, а
  старые сессии живы. Нужна одна транзакция на запись и отзыв.
- **`POST /backups` синхронный при `SERVER_WRITE_TIMEOUT` 15 с** (`backup_service.go:155`,
  `internal/config.go:20`). Длительность `VACUUM INTO` на проде не измерена; превысит таймаут —
  файл появится, а ответ не дойдёт, и повтор создаст второй. Измерить, затем поднять таймаут
  роута или сделать операцию асинхронной.
- **`PATCH /users/:id` с двумя полями применяет роль, затем активность, без отката**
  (`handlers/users.go:203`): `409` второго шага оставляет первый применённым. Клиент шлёт по одному
  полю, так что случай виден только другим клиентам.
