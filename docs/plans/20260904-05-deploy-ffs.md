# План 05 — Развёртывание на ffs.shatrov.tech

Пятый план перехода на API-only ([spec 005](../specs/005-api-only-redesign.md), решение A-11).
Одна топология: приложение + Caddy в одном compose на домашнем мини-сервере.

## Overview

- `deploy/docker-compose.yml` — единственный compose для прода: `app` + Caddy (`caddy:2.<minor>-alpine`,
  пришпилен дайджестом, Dependabot `docker-compose` для `/deploy`), Let's Encrypt автоматически, HTTP/3.
- Caddyfile без плагинных директив, без `/static`, с CSP для JSON и HSTS; `/health` через `log_skip`.
- Бэкапы — CLI `backup` того же бинарника по cron хоста; `backup.sh`, systemd-таймер и
  `make sqlite-backup` как отдельные механизмы уходят.
- nginx, certbot, fail2ban, `minimal`/`prod`/`nginx`/`caddy` варианты, native systemd — удаляются.

## Solution Overview

Caddy терминирует TLS и проксирует всё на `app:8080`, передавая `X-Forwarded-For`; приложение
доверяет только сети compose: `TRUSTED_PROXIES` задан **только** в `environment` compose, рядом с
`ipam.config.subnet` (в `.env` его нет — `environment` перекрывает `env_file`, и второе значение было бы
мёртвым). Лимитер логина — в приложении (план 03), поэтому Caddy ничего не ограничивает.

Бэкап: `family-budget-service backup` внутри контейнера пишет в `/backups` (bind-mount
`./backups`), cron хоста раз в сутки; ретеншен — `BACKUP_KEEP` (по умолчанию 30). Offsite-копия —
`GET /api/v1/backups/{name}/download` с телефона или `scp`.

## Technical Details

- `deploy/docker-compose.yml`: сервисы `app` (build из `..`, `env_file: .env`, volumes
  `./data:/data`, `./backups:/backups`, `user: 1000:1000`, `cap_drop: ALL`, `read_only: true` с
  tmpfs `/tmp`) и `caddy` (`80`, `443`, `443/udp`, volumes `Caddyfile`, `caddy_data`,
  `caddy_config`, `./logs/caddy`), `depends_on: app: condition: service_healthy`. Сеть `internal`
  с явной подсетью `ipam.config.subnet: 172.20.0.0/16` — иначе Docker выдаст случайную, и
  `TRUSTED_PROXIES` не совпадёт: `IPExtractor` откатится на адрес контейнера Caddy, и per-IP
  лимитер из плана 03 будет считать обоих пользователей одним клиентом.
- `.env.example`: `DOMAIN=ffs.shatrov.tech`, `ACME_EMAIL`, `DATABASE_PATH=/data/budget.db`,
  `BACKUP_DIR=/backups`, `BACKUP_KEEP=30`, `LOG_LEVEL=info`, `ENVIRONMENT=production`.
- Образ Caddy: `caddy:2.<minor>-alpine@sha256:…` (политика репозитория — всё пришпилено);
  `dependabot.yml`: `package-ecosystem: docker-compose`, `directory: /deploy`.
- Caddyfile: `{$DOMAIN}`; `encode zstd gzip`; заголовки `Strict-Transport-Security max-age=31536000`,
  `Content-Security-Policy "default-src 'none'; frame-ancestors 'none'"`, `X-Content-Type-Options nosniff`,
  `Referrer-Policy no-referrer`, `-Server`; `reverse_proxy app:8080`; JSON-лог с ротацией;
  `log_skip @health`. Без `rate_limit`, `@static`, `@login_post`.
- CLI `backup [--keep N]`. Сейчас ретеншен — константа `maxBackups = 10` (`backup_service.go:18`),
  `cleanupOldBackups` не экспортирован: `NewBackupService` получает `keep int` (константа
  `defaultBackupKeep = 30` — `mnd`), `CreateBackup` применяет его; выход 0/1; `RestoreBackup` удаляется
  из интерфейса и реализации вместе с тестами.
  cron: `0 3 * * * cd /opt/family-budget && docker compose exec -T app /app/family-budget-service backup`
  (`exec` обходит ENTRYPOINT, поэтому полный путь). В `upgrade.sh` — `docker compose run --rm --no-deps app backup`:
  ENTRYPOINT применяется, контейнер `app` может быть остановлен или нездоров.
- `install.sh`: `--domain` (по умолчанию `ffs.shatrov.tech`), `--email`; без генерации секретов;
  копирует `deploy/docker-compose.yml`, `Caddyfile`, `.env`; перед `up` удаляет сеть старой установки
  (`docker network rm family-budget_family-budget-net 2>/dev/null || true` — она на той же подсети);
  в конце печатает команду `setup` и строку cron. `upgrade.sh`/`uninstall.sh` — под один compose.
  `health-check.sh` без изменений.
- `ci.yml`: шаг `shellcheck deploy/scripts/*.sh deploy/scripts/lib/*.sh` (action по SHA, как остальные).
