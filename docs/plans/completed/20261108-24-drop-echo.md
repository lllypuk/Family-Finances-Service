# План 24. Уход с echo на net/http

## Overview

`vulncheck` в CI красный: у `labstack/echo` v4.15.4 восемь свежих `GO-2026-68xx`. v4.16.0 закрывает шесть, у
`GO-2026-6875` (proxy middleware) и `GO-2026-6872` (rate limiter) фикса нет. Ни то ни другое мы не зовём, но
govulncheck штатного ignore не имеет, а фильтр поверх `-json` (код выхода 0 при находках) легко ломает gate.
Echo держит лишь роутер, binder и пять middleware — уходим на `net/http` (`ServeMux` Go 1.22+), без новых
зависимостей. Решение принято 08.11.2026 вместе с codex (peer-chat); временного CVE-фильтра нет.

Блокирует MR !41 (распознавание через Яндекс): он вливается после этого плана.

**Контракт не меняется ни в чём**, включая неочевидное: неверный метод, `HEAD` и `OPTIONS` уходят в тот же
fallback, что у echo, — с middleware его группы, поэтому без токена внутри `/api/v1` это `401`, у чужой роли
`403`, иначе JSON `404`, но никогда не `405`. Метки `route` у метрик — прежние строки echo
(`/api/v1/transactions/:id`, `/*`, `/api/v1/*`, `/api/v1/users`, `/api/v1/users/*`) — это контракт с observability.
Сервер `v0.10.2`, релиза клиента нет.

**Не делаем:** `405` с `Allow`, `DisallowUnknownFields`, `415`, chi или другой роутер, правки клиента, XML/form-биндинг и `?pretty` (в контракте только JSON), тексты `error.details[].message` для битого JSON (клиент их не читает).

## Solution Overview

- **Хендлер** — `func(w http.ResponseWriter, r *http.Request) error`; адаптер `api.Handler` превращает ошибку
  в конверт (бывший `newAPIErrorHandler`), если ответ ещё не начат.
- **Роутер** `internal/application/router` (≈150 строк): `Register(method, template, h, mw...)`. Шаблон в
  echo-стиле, в `ServeMux` уходит как `{id}`; путь регистрируется в mux **один раз без метода**, внутри
  `map[method]Handler`. Промах по методу — не голый JSON 404, а fallback, который выбрал бы echo, с
  middleware его группы (auth, role) и **его** меткой; метку конкретного хендлера ставит только совпавший
  метод. `HEAD`/`OPTIONS` отдельно не регистрируются. Группа с middleware даёт два fallback'а — точный корень
  и `prefix/*`; корневой `/` — `/*`. Не subtree-redirect mux: `/api/v1/` не регистрируется как обычная группа.
  Тот же `Register` ведёт реестр маршрутов для OpenAPI-теста.
- **Метка route**: внешний middleware метрик кладёт в контекст указатель-держатель (приватный тип ключа,
  начальное значение `/*`), диспетчер пишет в него шаблон выбранного хендлера или fallback'а **до** auth/role
  middleware, наблюдатель читает после обработки ошибки. `r.Pattern` не используется: метки байт в байт прежние, копии
  `WithContext` не мешают.
- **Bind** → `decodeJSON(r, &req)` с семантикой `DefaultBinder` v4.15.4: тело пропускается только при
  `ContentLength == 0` (не по любому `io.EOF`: пустое chunked-тело остаётся 400); один `Decode`; неизвестные поля разрешены; хвост не проверяется; любая ошибка → 400 через
  `respondBindError`, `date.JSONField` по-прежнему даёт 422.
- **Middleware** — `func(http.Handler) http.Handler`, порядок снаружи внутрь: метрики → RequestID →
  recover (500 + `ObservePanic`, не пишет в начатый ответ) → timeout (`context.WithTimeout`, не
  `http.TimeoutHandler`; recognize пропускается) → логирование. Обёртка ResponseWriter одна, со статусом и
  `Unwrap() http.ResponseWriter` — без него `ResponseController` молча вернёт `ErrNotSupported`.
- **IP**: своя функция вместо `ExtractIPFromXFFHeader` — RemoteAddr не в доверенных → он; иначе
  `Header.Values("X-Forwarded-For")` справа налево до первого недоверенного; кривое значение → RemoteAddr.
- **Тело recognize**: `http.MaxBytesReader(11_000_000)` + ранний отказ по `ContentLength`;
  `errors.As(*http.MaxBytesError)` → 413.
