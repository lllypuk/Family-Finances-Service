# План 21. Светлая тема по настройке телефона

## Overview

Клиент рисует одну тёмную тему (`theme/Colors.kt`: «светлого варианта в v1 нет»). На телефоне со светлой
системной темой приложение остаётся тёмным пятном среди светлых экранов. План добавляет светлую палитру,
выбор по системной настройке и переключатель в настройках: «Система / Светлая / Тёмная».

- Клиент `0.13.0`, контракт `/api/v1` не трогается — сервер не участвует, старые APK ничего не теряют.
- Один и тот же характер в обеих темах: холодная морская зелень (teal) как единственный акцент, ink-текст,
  «выше — светлее» для слоёв. Светлая тема — не инверсия тёмной и не кремовая «бумага», а тот же бренд днём.

**Не делаем:** динамические цвета Material You, отдельную палитру для AMOLED, тему по расписанию,
перекраску иконки приложения, серверное хранение выбора, `recreate()` при переключении.

## Solution Overview

Вариант **B** (без AppCompat): переопределение живёт в `SharedPreferences` и доходит до трёх мест:

1. **Compose** — `AppTheme(mode = ThemeMode.System, content)` выбирает `LightColors`/`DarkColors` через
   `@Composable ThemeMode.isDark()`: `System → isSystemInDarkTheme()`, `Light → false`, `Dark → true`.
   Схема M3 собирается один раз на палитру. `AppTheme` остаётся чистым — никаких обращений к окну: его
   вызывают 23 тестовых файла с активити под `createComposeRule`, и путь через `PhoneWindow` без shadow
   уронил бы весь экранный набор. С дефолтом `System` существующие тесты с этого момента рендерят **светлую**
   палитру (Robolectric по умолчанию `notnight`) — сознательно, цвет там нигде не проверяется.
2. **Окно** — `values/themes.xml` со светлым родителем и `values-night/themes.xml` с тёмным, оба с
   `windowBackground` = `canvas` своей темы и `windowLightStatusBar`/`windowLightNavigationBar`. Это полностью
   закрывает режим «Система»: и splash, и первый кадр — из темы по квалификатору. При переопределении
   `MainActivity.onCreate` читает хранилище синхронно и вызывает `setTheme(...)` до `setContent`; splash при
   этом всё равно системного цвета (он рисуется из темы манифеста до процесса) — короткая вспышка при
   переопределении принимается, `recreate()` ради неё не делаем.
3. **Системные панели** — статические значения из XML покрывают «Систему»; для переопределения `MainActivity`
   в `SideEffect` ставит `WindowInsetsControllerCompat.isAppearanceLightStatusBars/NavigationBars = !dark`
   (`androidx.core` уже в зависимостях; `enableEdgeToEdge()` не нужен — с targetSdk 37 окно и так edge-to-edge).

Отказ от AppCompat DayNight: новая зависимость, `AppCompatActivity`, смена родителя темы и `recreate()`
при переключении ради одной настройки.

Переключение в настройках применяется живо (`StateFlow` → `collectAsStateWithLifecycle` в `MainActivity`),
без пересоздания.

## Technical Details

### Палитра (frontend-design)

Принципы: один акцент — teal, знак суммы всегда и текстом (уже так); «выше — светлее» в обеих темах, чтобы
`elevated` над `canvas` читался одинаково; обводка `action` держит выбранность, потому что
`elevated`:`canvas` в светлой ~1,13:1. Холодный оттенок серых (`canvas` с зелёно-синим подмесом), не
кремовый — тот же бренд, что и ночью.

| токен | Dark (есть) | Light | назначение в светлой |
|---|---|---|---|
| canvas | `#071014` | `#EDF2F2` | фон экрана, чуть темнее карточек |
| surface | `#121B20` | `#F7FAFA` | карточки, поля |
| elevated | `#19252B` | `#FFFFFF` | выбранный сегмент, диалоги |
| border | `#334248` | `#C3D0D2` | обводки, разделители (1,4:1 — декоративные) |
| textPrimary | `#F2F5F5` | `#0F1C20` | ink, 16,6:1 на surface |
| textSecondary | `#9CABAF` | `#4F6166` | 5,75:1 на canvas; кольцо кружка категории |
| textInverse | `#06110F` | `#F7FAFA` | текст на `action` (5,7:1) и `expense` (5,2:1) |
| action | `#20D1B0` | `#087060` | 5,3:1 на canvas |
| income | `#5FD37A` | `#177A35` | 4,8:1 на canvas |
| warning | `#F2A833` | `#9A5B00` | 4,8:1 на canvas |
| expense | `#F25A52` | `#C4322B` | 4,8:1 на canvas |
| disabled | `#59666A` | `#9AA7AA` | контраст не требуется |

Цифры проверены расчётом при ревью плана; тест контраста (Task 1) — источник истины, при провале токен
сдвигается на шаг, таблица правится.

Мэппинг `appColorScheme` меняется в двух ролях: `onError` → `textInverse` для обеих тем (в тёмной
`textPrimary` на `expense` даёт 3,0:1, `textInverse` — 5,8:1; роль сейчас никем не читается, правка —
на будущее), и `surfaceTint = action` — единственная незаданная роль, которая утекает цветом (baseline
`#6750A4`) в tonal elevation `Surface` и прокрученный `TopAppBar`. Светлая схема собирается через
`lightColorScheme(...)`, чтобы остальные незаданные роли (`scrim`, `inverseSurface`) брались из светлого baseline.

### Режим

```kotlin
// theme/Theme.kt
enum class ThemeMode { System, Light, Dark }   // хранится строкой, неизвестная → System
@Composable fun ThemeMode.isDark(): Boolean

// ThemeStore.kt, рядом с LastAccountStore.kt
interface ThemeStore { val mode: StateFlow<ThemeMode>; fun write(mode: ThemeMode) }
class MemoryThemeStore(initial: ThemeMode = ThemeMode.System) : ThemeStore
class PrefsThemeStore(context: Context) : ThemeStore   // prefs "ui", ключ "theme_mode"
```

`AppGraph.theme: ThemeStore = MemoryThemeStore()`; `create(...)` подставляет `PrefsThemeStore(context)`.

### Ресурсы

`values/colors.xml`: `canvas_light = #EDF2F2`, `canvas_dark = #071014`; `ic_launcher_background` остаётся
`#071014` (иконка не темизируется, комментарий поправить).

`values/themes.xml`:
- `Theme.FamilyFinances` ← `android:Theme.Material.Light.NoActionBar`, `windowBackground = @color/canvas_light`,
  `windowLightStatusBar = true`, `windowLightNavigationBar = true`;
- `Theme.FamilyFinances.Light` и `Theme.FamilyFinances.Dark` — **обязательно с явным `parent=`** на
  `android:Theme.Material.Light.NoActionBar` / `android:Theme.Material.NoActionBar` и своими атрибутами.
  Без `parent=` точечное имя наследует `Theme.FamilyFinances` *с текущими квалификаторами*: под `night`
  `.Light` вышла бы тёмной — ровно в том случае, ради которого существует.

`values-night/themes.xml` переопределяет только `Theme.FamilyFinances` (тёмный родитель, `canvas_dark`,
оба `windowLight* = false`).

### Точка категории

`CategoryDot(hex: String, modifier: Modifier = Modifier)` в `ui/categories/`: заливка
`parseCategoryColor(hex, outline)` + кольцо `border(1.dp, LocalAppColors.current.textSecondary)` — `border`
(1,4:1 на canvas) бледный цвет не спасает, кольцу нужно ≥ 3:1. Переводится **только** точка списка;
swatch палитры в `CategoryEditScreen` остаётся как есть — его 2dp `onSurface`-кольцо означает выбранность,
и постоянное кольцо её размыло бы.

**Ручная проверка**: холодный старт в обеих системных темах и при обоих переопределениях (вспышка splash при
переопределении видна только глазом). Ночной режим по расписанию телефона **пересоздаёт** активити
(`configChanges` не объявлен): открытая форма операции, идущее распознавание и `rememberSaveable`-экран
должны её пережить (`ScopedModels` — retained `ViewModel`; `offerShared` пропускается при
`savedInstanceState != null`), палитра после пересоздания — новая.
